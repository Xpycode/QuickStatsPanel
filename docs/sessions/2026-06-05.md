# Session — 2026-06-05

## Focus
Esc-to-dismiss for the HUD panel (D-010).

## Problem
The panel is a `.nonactivatingPanel` summoned with `orderFrontRegardless()` and
deliberately never becomes key (D-001), so `keyDown` / SwiftUI `.onKeyPress`
never reach it — Esc goes to whatever app has focus. Click-away already uses a
permission-free *mouse* global monitor, but a *keyboard* global monitor needs
Input-Monitoring permission (breaks D-002/D-003).

## Decision — D-010
Bare Escape via Carbon `RegisterEventHotKey`, registered **only while the panel
is visible** and torn down on hide. Permission-free, focus-independent, no focus
theft — the same mechanism proven for the toggle hotkey. Toggle hotkey stays the
primary dismiss; Esc + click-away are conveniences.

**Trade-off accepted:** bare Escape is captured system-wide while the panel is
on screen (transient, so acceptable). User confirmed this option over
make-panel-key (focus theft) and skip-Esc.

## Changes
- **`Services/HotKeyService.swift`** — added per-instance `id` (init param),
  `.escape` binding, and **EventHotKeyID filtering** in the Carbon callback
  (`kEventParamDirectObject` → `typeEventHotKeyID`). Fixes a latent bug: Carbon
  dispatches every press to *all* installed app-level handlers, so without
  filtering a second service would also fire on the toggle hotkey.
- **`Panel/PanelWindowController.swift`** — new `onVisibilityChanged: ((Bool) -> Void)?`,
  fired in `show(true)` / `hide(false)`; `hide()` guarded with `guard panel != nil`
  so redundant hides don't double-fire.
- **`AppDelegate.swift`** — second `HotKeyService(id: 2)` = `dismissHotKey`;
  `installEscToDismiss()` registers `.escape` on show, unregisters on hide via
  the visibility signal (covers toggle / click-away / Esc paths); cleanup added
  to `applicationWillTerminate`.

# Session — 2026-06-05 (afternoon): Phase A stats

## Focus
Add three new permission-free stat tiles: **Load Average, Uptime, Top Process**.
Planned with parallel research agents (codebase map + API research + the
permission question) before writing code.

## Research findings that shaped the build
- **Uptime:** use `kern.boottime`, NOT `ProcessInfo.systemUptime` — the latter
  only counts *awake* time, so on any Mac that sleeps it reads low. `kern.boottime`
  matches `uptime(1)` / Activity Monitor.
- **Top process permission (the risky bit):** traced XNU `proc_security_policy` —
  enumerating PIDs and reading a process *name/path* is permission-free for any
  process, but reading *memory/CPU* is same-user-gated (foreign procs → EPERM).
  So it's honestly "top *user* process," not system-wide. True system-wide top
  needs a root helper (`sysmond`, like Activity Monitor) → rejected, breaks
  zero-permission stance.
- **Memory before CPU:** memory is a snapshot (`ri_phys_footprint`, matches
  Activity Monitor's Memory column) → correct on the first summon. CPU% is
  delta-based (blank first frame) → deferred as a fast-follow.

## Decisions — D-011, D-012
- **D-011:** Load Average (`getloadavg`, 1-min headline, band = load÷activeCores)
  + Uptime (`kern.boottime`, compact "3d 4h", neutral tint).
- **D-012:** Top Process = top *user* process by memory via `libproc`, no
  privileged helper. Value headline, name in popover (preserves D-008 fixed-width).

## Changes
- **`Sampling/LoadAverageSampler.swift`** (new) — `getloadavg(3)`, absolute snapshot.
- **`Sampling/UptimeSampler.swift`** (new) — `sysctlbyname("kern.boottime")`.
- **`Sampling/TopProcessSampler.swift`** (new) — `proc_listallpids` +
  `proc_pid_rusage(RUSAGE_INFO_V4)` (EPERM-skip) + `proc_pidpath` name. The
  rusage buffer needs `withMemoryRebound(to: rusage_info_t?.self)` (C param is an
  opaque `void *`). `import Darwin`.
- **`Model/StatDescriptor.swift`** — +3 `StatKind` cases, +3 `displayName`/
  `settingsSymbol` branches, +3 `descriptor(for:)` branches (top-process guarded
  by `hasProcess`).
- **`Model/StatsStore.swift`** — +3 sample props, +3 sampler owners, start/stop wiring.
- **`Model/AppSettings.swift`** — new `knownStats` UserDefaults record: new
  `StatKind`s default ON for existing users *without* re-enabling deliberately
  disabled stats (a disabled stat and a brand-new stat are otherwise
  indistinguishable, since only enabled stats are persisted). Seeds the legacy
  five on first upgrade.
- **`Views/SettingsView.swift`** — stat-list height now scales with stat count
  (was hardcoded `170`, would clip at 8 rows).
- **Zero view changes** to `StatsStripView` / `StatTileView` — the data-driven
  chokepoint absorbed all three stats.

# Session — 2026-06-05 (evening): Top-process lists in popovers + app grouping (D-013)

## Focus
Fast-follow to D-012. Started as "top-process CPU mode"; via discussion it became
the **iStat-Menus model**: fold top-process lists into the CPU / Memory / Disk
tile popovers and **retire** the standalone Top Process tile.

## How the shape changed (user-driven)
- Offered "two tiles" vs "memory/CPU toggle"; user countered with "use the CPU
  and RAM *dropdowns* like iStat Menus" → much cleaner. Adopted.
- Scope chosen: top-5 lists in **CPU, Memory, Disk** popovers; standalone tile
  **retired**; network requested but **excluded** (see below).

## Research findings that shaped the build
- **⚠️ Units (decisive):** `ri_user_time`/`ri_system_time` in `rusage_info_v4`
  are **mach absolute time units, NOT nanoseconds** — kernel writes `rm_time_mach`
  straight through (XNU `osfmk/kern/bsd_kern.c` `fill_task_rusage`; corroborated by
  osquery #7459). On Apple Silicon a tick ≈ 41.67 ns → treating as ns under-reads
  CPU ~24×. Fix: convert via `mach_timebase_info`, wall time via `mach_absolute_time()`
  (CPU% cancels mach÷mach; disk bytes/sec needs the real-seconds conversion).
  `ri_diskio_bytes{read,written}` confirmed present in v4, in bytes.
- **Per-process network = impossible permission-free:** no public API; `nettop`
  uses the private `NetworkStatistics.framework`, ES `responsible_audit_token`
  needs an Apple entitlement + FDA. Network tile stays system-wide Down/Up.
- **Responsible-app attribution = private only:** `responsibility_get_pid_responsible_for_pid`
  (libquarantine) is permission-free for same-user but **private** (App-Store-
  rejecting, OS-fragile). `ppid` is useless (WebKit XPC parent = launchd). Chose
  to **prettify names** instead (public-only), per D-012's "stay clean" precedent.

## Decision — D-013
Top-process lists live in the CPU/Mem/Disk popovers; standalone `.topProcess`
retired (auto-migrates). One `rusage_info_v4` pass ranks 3 ways. Processes grouped
by app; XPC/version-named binaries get readable names; no private APIs.

## Changes
- **`Sampling/TopProcessSampler.swift`** — rewritten. `TopProcessSample` →
  `TopProcessesSample` (`byCPU`/`byMemory`/`byDiskIO: [ProcStat]` + row formatters).
  Per-PID `prevCPU`/`prevDisk` + `prevWall` for rate deltas; `secondsPerMachTick`
  via `mach_timebase_info`. **Grouped by app** (`appGroupName(forPath:)`, summed
  then ranked). Per-PID `nameCache` (pruned to live PIDs each tick) keeps
  `proc_pidpath` to once-per-process. `ProcStat` now keyed by app `name` (no pid).
- **`appGroupName(forPath:)` 3 tiers** — (1) outermost `.app`; (2) `.xpc`/`.appex`
  → `prettify` (reverse-DNS → last component → camelCase-split, e.g.
  `com.apple.WebKit.WebContent` → "Web Content"); (3) plain exec, **climbing past**
  version-like tokens + generic dirs (`versions`/`bin`/…) so `…/claude/versions/2.1.165`
  → "claude". Helpers (`isVersionLike`, `genericPathComponents`).
- **`Model/StatDescriptor.swift`** — removed `.topProcess` from `StatKind` +
  switches; `StatDescriptor` gained optional `ProcessSection` (+ explicit init
  with default); CPU/Mem/Disk descriptors append a `section("Top by …", rows)`
  (auto-hidden while empty so two-tick rates don't flash an empty header).
- **`Model/StatsStore.swift`** — `topProcess` → `topProcesses: TopProcessesSample`.
- **`Views/StatTileView.swift`** — renders the process section (divider + title +
  name/value rows; name `lineLimit(1)`/`.truncationMode(.middle)`; index-keyed).
- **`Views/StatsStripView.swift`** — passes `processSection` through.
- **`SettingsView`/`AppSettings`** — no code change; `.topProcess` removal
  auto-migrates via `compactMap(StatKind.init(rawValue:))`.

## State
`** BUILD SUCCEEDED **` (clean), relaunched after each step. `appGroupName`
logic unit-checked standalone (`swift` snippets) against real machine paths
before each build.
