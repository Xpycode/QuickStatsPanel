### Q1 — Sparkle: no, and the backlog's framing was wrong

QSP has **no updater of any kind**: zero code references, no `packages:` in `project.yml`,
and `scripts/package-dmg.sh` documents the absence ("No Sparkle → no inside-out nested
re-signing, no appcast step").

The backlog's "**Sparkle vs SilentUpdateKit**" is a false dichotomy — they are different halves:

- **Sparkle 2** is the de-facto house standard (ClipSmart, Magpie, DiskVerdict, Conjoyn,
  TimeCodeEditor, ScreenshotFromVideos, VideoContainerSwitcher). Discovery + install + UI.
- **SilentUpdateKit** is explicitly *"free of any appcast/scanner concepts — feed parsing and
  app discovery are the caller's job."* Install half only: verify Sparkle-format Ed25519 sig via
  CryptoKit, Team-ID match, extract, quit, swap bundle, old version → Trash for rollback.
  **No Sparkle.framework**, so no nested XPC signing — which is exactly what the current
  DMG pipeline benefits from.

Recommendation (not yet decided): **SilentUpdateKit + a small feed check** fits an
`LSUIElement` HUD better than full Sparkle, and stays appcast-interoperable if we graduate later.

⚠️ **Portfolio-wide flag (details deliberately omitted — this repo is public):** one sibling app's
`project.yml` pins Sparkle to a minimum version citing fixed security advisories in the older line,
and warns against the version some other portfolio apps still use. Two of them do still use it.
Not a QSP issue (QSP has no Sparkle at all) — worth a separate, private portfolio sweep.

### Q2 research — iStat Menus 6.73.1 (binary-verified) + exelban/stats (source)

**Headline finding, and it reverses the original proposal: neither product offers a
free-vs-used radio. Both show BOTH.**

- iStat Menus' Memory and Disks modules ship an element literally named **`USED/FREE`** —
  two lines, independently colourable, "Show Label" toggle. No radio anywhere.
  (Read from the shipped 6.73.1 prefs nibs + binary string table, not marketing copy.)
- exelban/stats hardcodes `Mini`/`BarChart`/`PieChart` → **used** %; its `MemoryWidget`
  renders free *and* used as two rows.
- The **only** true pick-one enum in either product is Stats' Speed widget
  (`Kit/types.swift:126`): `output/input | input/output | input | output`, plus
  "Display mode" = `Automatic / One row / Two rows`.
- The **only** mechanism that lets a user say "free, not used" is Stats' **text template**
  (`Kit/Widgets/Text.swift:83`): `$capacity.free/$capacity.total`, `$mem.used`, `$pressure.value`,
  `$interface.displayName`, etc. Power-user surface — logged as backlog, not for v1.

**Structural lesson both products converged on:** they separate **which value** from
**how it's drawn**. iStat's elements are render-types (`BAR GRAPH` / `PERCENTAGE` / `USED/FREE`);
Stats separates module settings (data) from widget settings (presentation). A single flat
`TileMetric` enum would conflate the two axes into N×M cases.

Cheap wins worth stealing from Stats' Memory widget: **"Reverse order"** (swap which of
free/used leads) and **"Show symbols"** (`F:` / `U:` prefixes).

### Q3 — graphs: technically green, cheaper than expected

The make-or-break fact: **all samplers already run un-gated** (`Model/StatsStore.swift:108-119`;
only the costly `top` sampler is visibility-gated at line 119). So a history buffer is fed while
the panel is hidden → **graphs are populated the instant the hotkey fires**, not empty-and-filling.
Cost: **~30 KB RAM** (60 samples × 11 stats) and **zero extra CPU** — we already pay for the
sampling and currently throw away everything older than one tick.

Constraints checked, neither blocks:
- `DetailPanelController.swift:45` measures the card once per open — a **fixed-size** chart is
  the well-behaved case. D-024's objection was aesthetic, not technical.
- D-008 jitter rule untouched: a sparkline is fixed-width by construction.

**Empirical support for reversing D-024:** iStat Menus ships **`HISTORY GRAPH` as a menu-bar
element** (alongside `BAR`/`PIE`/`CIRCULAR GRAPH`, `PERCENTAGE`) for CPU, GPU, Memory and Disk
activity, plus a network graph with `Stacked / Opposed / Centered / System` modes. A live history
graph at ~20 pt in a system-wide strip is mainstream, not inherently "deep monitoring".
Both products graph **CPU, GPU, Memory, Network, Disk *activity*** — never disk *capacity* or uptime.

**Renderer recommendation:** hand-drawn `Canvas`/`Path` sparkline used at two sizes (small in
strip, larger in card), **not Swift Charts**. Precedent: D-015 threw out the native `.popover`
precisely because system chrome clashed with the flat strip. Checked the house convention —
DiskVerdict's `TrendChart.swift` is **437 lines** with least-squares regression, axes and
captions: right for an analytics window, wrong for a 36 pt strip.

### Bug found: Disk "Free" is ~17 GB pessimistic vs Finder

`Sampling/DiskSampler.swift:108` uses `statfs` `f_bavail`, which excludes purgeable space.
Measured on the M4 Pro (independently twice — direct `swiftc` probe and the research agent,
agreeing to ~0.2 GB):

```
statfs f_bavail = volumeAvailableCapacityKey = df = Disk Utility .... 600.62 GB   ← QSP shows this
volumeAvailableCapacityForImportantUsageKey ........................ 617.24 GB   ← Finder shows this
CSDiskSpaceGetRecoveryEstimate()  (purgeable) ....................... 16.62 GB
                                                       600.62 + 16.62 = 617.24 ✓
```

Finder cross-checked via `osascript` (`free space of startup disk`) — matched to within 82 KB.
Harmless as one detail row; becomes a "your app is wrong" report the moment *free* is a headline
the user deliberately selected.

- exelban/stats calls `CSDiskSpaceGetRecoveryEstimate` (CoreServices, cached 30 s) and returns
  `free + purgeable` specifically to match Finder — `Modules/Disk/readers.swift:144`.
  **Undocumented SPI** — consistent with QSP's posture (IOReport + IOHID already proven through
  notarization 2026-07-03), but it is another one.
- `volumeAvailableCapacityForImportantUsageKey` is a **required-reason API** — needs declaring if
  QSP ever ships a `PrivacyInfo.xcprivacy`. None today (direct distribution). `statfs` needs none.
- `…ForOpportunisticUsage` (596.46 GB) is *smaller* than plain available — **never** display it.
- The existing `used = total − f_bavail` derivation (line 109) is **correct** — it captures whole
  APFS-container usage rather than the sealed System volume's 12 GB. Don't "fix" that.
- Bjango's own help page contradicts itself on purgeable ("hides … match Finder" vs "set to hidden
  … match Disk Utility"). The measurements above are authoritative over the doc.

**Design detail not to lose** (worked out, not yet written down anywhere else): size the history

user-configurable, so a fixed 60-sample buffer means 60 s at 1 s but 5 minutes at 5 s. And

history must be **deliberately cleared** there — splicing points from different time bases
produces a silently lying graph.

**Store history as the full sample struct**, not just the plotted scalar, so switching metric
re-plots the past correctly instead of blanking the graph.

### The reference images changed the design (and settled an open question)

The user's screenshots (iStat's Network and Disk dropdowns) show discrete mirrored bars around a
dotted zero line, not a line sparkline — plus a **peak legend row**. That legend answered the
scaling question that had been left open for the user to decide:

> Network peak ↑ = **124 KB/s**, peak ↓ = **34.0 MB/s** — a **274×** difference — yet the pink and
> blue bars are of comparable height. So each series is normalized to **its own** peak, and the
> peak is **printed beside the graph**. A rebasing scale is only dishonest when unlabelled.

Second consequence, unplanned: the mirrored form distinguishes two series by **position**, not
hue — so it survives the Mono preset (which suppresses all status color, `Theme.swift:166`) with
no extra work. A stacked or overlaid line chart would not have.

### Decisions worth keeping (full entry: `decisions.md` D-025)

- **Defaults reproduce the shipped strip byte for byte.** Research says combined is the norm, but
  defaulting to it would silently widen every existing user's strip on upgrade — under D-008's
  content-driven width that is a visible event, not a cosmetic one.
- **Markers only in combined modes.** `U`/`F`/`↓` appear when two numbers sit side by side and
  would be ambiguous; a lone value is unambiguous by construction, so single modes stay as narrow
  as today.
- **`upper`/`lower`, not `primary`/`secondary`.** "Primary" already means *which value the tile
  headlines*; for Network that's Download, but the reference draws Upload on top. Two orderings
  under one word is how a graph ends up mirrored backwards.
- **Peak memory lives in the store, not the view** — `@ObservationIgnored`, the same shape as the
  existing band hysteresis, ignored precisely so a body-read write can't loop.
- **Options beside the row, never in it** — a second control in the row re-enters the macOS 26
  drag conflict D-024 just fixed.
