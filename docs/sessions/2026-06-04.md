# Session: 2026-06-04 (v1.1 stats — Network + Battery samplers)

## Goal
Add the two v1.1 stats from the roadmap: Network up/down throughput and Battery.

## Progress
- **NetworkSampler (new, permission-free):** throughput via `getifaddrs(3)` — counters
  (`ifi_ibytes`/`ifi_obytes`) live on each interface's `AF_LINK` record's `if_data`.
  Cumulative-since-boot → per-tick delta ÷ interval, structurally identical to DiskSampler
  (same timer skeleton + `previous…` delta + monotonic-guard).
  - **Interface filter is a real design choice** → extracted to `shouldCount(interfaceName:flags:)`.
    User chose **count everything** (`return true`) as the get-it-on-screen-first default;
    one-line tighten to `(flags & IFF_LOOPBACK) == 0` documented in-place. Trade-off: lo0's
    local-only traffic inflates the reading, so it's never truly 0 at idle.
  - Net tile: headline = down rate, popover = Down/Up. `activityPercent` maps total throughput
    against a 12.5 MB/s (100 Mbit) soft reference for the color band (tunable like Theme).
- **BatterySampler (new, permission-free):** IOKit Power Sources (`IOKit.ps`) — same snapshot
  the menu bar reads. NOT a delta: each tick reads absolute state (charge %, charging, time).
  - `IOPSCopyPowerSourcesInfo`/`List` → Create Rule → `takeRetainedValue`; `IOPSGetPowerSourceDescription`
    → Get Rule → `takeUnretainedValue` (name prefix = ownership contract).
  - Desktop Macs report no source → `isPresent: false` → **tile hidden entirely** in StatsStripView.
  - Battery color band is **inverted**: feed `100 - percent` into `Theme.loadColor` so low charge = hot.
  - Dynamic SF Symbol (`battery.Npercent[.bolt]`) reflects level + charging, like the menu bar.
  - Tile: headline = charge %, popover = Charge/State/Time. Time uses IOKit -1 = calculating → "—".
- Both wired into `StatsStore` (start/stop/publish). `xcodegen generate` re-run for the new files.
- **`** BUILD SUCCEEDED **`** (zero errors); relaunched. Pending on-screen user verify via ⌃⌥⌘Q.

## Decisions
- Network throughput is **permission-free** (`getifaddrs`), consistent with D-002/D-003 — no
  privileged packet capture. Interface inclusion is a pluggable predicate (`shouldCount`),
  currently count-everything; revisit for loopback exclusion if idle reading is distracting.
- Battery is **permission-free** IOKit Power Sources; tile is **conditional on `isPresent`** so
  the HUD adapts to desktop vs portable Macs without config.

## Next
1. **On-screen verify** (⌃⌥⌘Q): Network ticks live; Battery shows on portables / hidden on desktop.
2. In-panel gear → real settings (hotkey rebind, stat selection, interval, anchor, height) + Quit.
3. **USER:** tune `Theme.loadColor` color bands (still the open design Q); decide if Network should
   drop loopback (`shouldCount`) and the battery `activityPercent` reference feels right.
4. Consider **data-driven strip** refactor — 5 tiles + a conditional is nudging SwiftUI's
   type-checker; an array of tile descriptors would scale better and enable stat selection.
5. Polish backlog (unchanged): memory precision, cornerRadius, app icon, first-run hint, signing.

# Session: 2026-06-04 (data-driven strip refactor)

- **New `Model/StatDescriptor.swift`:**

    Declaration order = display order; the stable identity a future stat-selection setting

# Session: 2026-06-04 (in-panel settings — all five)

## Goal
Build the in-panel settings (Next #1). Scoped via two questions → user chose **gear opens a
real Settings window** (not an in-panel popover) and **all five settings now**, including
hotkey rebind.

## Progress
- **`Model/AppSettings.swift` (new):** `@Observable @MainActor` singleton, `UserDefaults`-backed.
  Single source of truth shared by `AppDelegate`'s imperative objects *and* the settings view —
  bridges two disconnected object graphs. Key insight = **passive vs. active settings**: anchor /
  strip height / stat order+enabled are read lazily (at summon / in `body`, Observation refreshes);
  interval + hotkey *push* via `didSet` hooks `onIntervalChanged` (→ `store.restart()`) and
  `onHotKeyChanged` (→ re-register). Init loads from defaults with safe fallbacks; new `StatKind`s
  appended so a stored order never silently drops one.
- **`Model/PanelAnchor.swift` (new):** enum `cursor / screenCenter / topCenter / bottomCenter`;
  origin math lives in `PanelWindowController` (needs visibleFrame + measured size, clamped).
- **`visibleStats` now composes** order → enabled → availability at the one chokepoint; `StatKind`
  gained `displayName` + `settingsSymbol`.
- **`StatsStore`:** interval read from settings; added `restart()` (stop+start) for interval changes.
- **`StatsStripView`:** trailing **gear tile** (always present, even with all stats off) + height
  from `AppSettings.shared.stripHeight`.
- **`HotKeyRecorderView` (new) + `Services/HotKeyBinding+Display.swift` (new):** click-to-record via
  a local `keyDown` monitor that *returns nil* (swallows the keystroke); `NSEvent`→Carbon modifier
  conversion; `displayString` (⌃⌥⌘Q) with a keycode→label map. **Validation (user's call): reject
  Shift-only, require ≥1 of ⌘/⌥/⌃** — single bitmask test against the strong-modifier mask.
- **`SettingsView`:** real `Form` — drag-reorder + toggle stats (List `.onMove`), interval slider
  (0.25–5s), anchor picker, height slider (22–44pt), hotkey recorder, Reset to Defaults, Quit.
- **Gear → settings window bug + fix:** first wired gear to `NSApp.sendAction(showSettingsWindow:)`.
  User reported **no window appears, panel just loses focus** — the classic `LSUIElement` failure
  (`activate()` runs, selector silently no-ops). Replaced with **`Panel/SettingsWindowController.swift`
  (new):** a self-managed `NSWindow` hosting `SettingsView`, `activate` + `makeKeyAndOrderFront`
  (same self-managed-AppKit approach as the panel; a real key window is also what the recorder needs).
  `QuickStatsPanelApp`'s `Settings` scene reduced to an empty placeholder so the gear is the single path.
- **`** BUILD SUCCEEDED **`** clean (no warnings) throughout; **user confirmed on screen** — settings
  window opens with all five sections rendering correctly (screenshot). SourceKit "cannot find type"
  noise all session, as before — false positives, real `xcodebuild` clean.

## Decisions
- **D-009** Gear opens a settings **window** (not a popover): the non-activating panel can't become
  key, but the hotkey recorder needs a key window. **Mechanism = self-managed `NSWindow`**, NOT the

  `AppSettings.shared` singleton + passive-read / active-`didSet`-hook split. Anchor is now an enum
