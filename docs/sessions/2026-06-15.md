# Session — 2026-06-15

**Focus:** Make the strip repositionable and stickable — drag-to-move, a
right-click menu, a "Keep on Screen" pin (menu + rebindable hotkey), and a
pinned indicator. Plus a fix for Settings opening behind the floating strip.
(D-016.)

## What happened

Five related changes, all on `main`, built clean (0 warnings) and verified on
screen by the user step by step.

### 1. Drag to move (persists as a custom position)
- `PanelWindowController` panel flipped to `isMovable + isMovableByWindowBackground`.
  Tiles/gear are SwiftUI controls that consume their own mouse-downs, so only the
  empty background drags the window; a plain tap never moves it.
- New `customOrigin` summon path: `toggle/show(anchor:customOrigin:)` and
  `origin(forSize:anchor:customOrigin:)` — a custom origin **wins over the anchor**
  and is clamped to the screen it lands on.
- Drag capture: a block-based `NSWindow.didMoveNotification` observer (wrapped in
  `MainActor.assumeIsolated` to stay clean under `complete` strict concurrency —
  same shape as `AppSettings`'s accessibility observer, deliberately **not** an
  `NSWindowDelegate` conformance). It tells genuine user drags from our own
  `setFrame` echoes by comparing against `lastAppliedOrigin` (exact match = our
  move, skip). Fires `onPanelMoved`, which `AppDelegate` persists to
  `AppSettings.customPosition` (a `CGPoint?`).
- `AppSettings.anchor` `didSet` now clears `customPosition` — an explicit anchor
  pick in Settings supersedes a dragged spot (else picking "Top center" would
  silently do nothing).

### 2. Right-click menu
- `FirstMouseHostingView` gained a `contextMenuProvider` + a `rightMouseDown`
  override that pops an `NSMenu` (SwiftUI `.contextMenu` is unreliable on a
  non-key, non-activating panel). The right-click is local to our window, so it
  never reaches the global click-away monitor — the strip stays put while the
  menu is open.
- `AppDelegate.makePanelMenu()` (rebuilt per right-click so item state is live):
  **Keep on Screen** (✓ when pinned), **Reset Position** (enabled only when a
  custom position exists), **Settings…**, **Quit**. @objc actions on the
  `@MainActor` delegate.

### 3. Pin — "Keep on Screen"
- Per-summon `isPinned`. While pinned, **only** the click-away monitor is gated
  (`guard … !isPinned`); Esc and the toggle hotkey still hide it (user chose "Esc
  unpins and dismisses", so Esc is intentionally not gated). `isPinned` resets on
  every hide path so a fresh summon is never stuck pinned.
- Rebindable hotkey: default **⌃⌥⌘P** (`HotKeyService.Binding.defaultPin`), stored
  as `AppSettings.pinHotKey`, recorded via the existing `HotKeyRecorderView` in a
  new Settings row. A 4th scoped `HotKeyService(id: 4)` registered/unregistered in
  the `onVisibilityChanged` closure beside Esc/⌘, (D-010 pattern) — read at
  register time, so a rebind applies on next summon with no live re-register hook.

### 4. Settings no longer hidden behind the strip
- `openSettings()` now calls `panel.hide()` first. The strip floats at `.floating`
  level, so it sat on top of the normal-level Settings window (worse when pinned).
  Hiding also tidies up: pin resets, detail/hint cards close, scoped hotkeys
  unregister — and it's why the pin hotkey needs no live re-register.

### 5. Pinned indicator (thumbtack)
- A `pin.fill` glyph (theme-tinted `secondaryText`) shown only while pinned.
- First tried a corner **overlay** → it collided with the first tile and rode the
  top edge (the strip is snug, no spare gutter). Switched to a **reserved inline
  leading slot**: always laid out, `opacity` 0↔1. The strip's width is measured
  once per summon (`fittingSize`, D-008) and frozen, so an `if`-conditional element
  would reflow/clip on a mid-display toggle — the reserved slot fades in place with
  zero layout change. User confirmed it looks right.
- To make it observable, `isPinned` lives on the `@Observable AppSettings.shared`
  (transient, not persisted); `AppDelegate` keeps a computed `isPinned` forwarding
  to it so its call sites are unchanged and the SwiftUI strip reacts live.

## Files

- `AppDelegate.swift` — pin gating, NSMenu + @objc actions, 4th hotkey,

# Session 2 — 2026-06-15 (GPU + Fan stats: pick → spec → plan → Wave 1)

**Focus:** Kick off the next roadmap item, **GPU / temps / fans**. Chose to split
it: **D-017** = GPU + Fan tiles (this session), **D-018** = Temperatures (later).
Research-driven spec → wave plan → executed Wave 1 (the two samplers).

## What happened

### Feature choice + de-risking research
- Picked GPU/temps/fans off the roadmap. A research agent (web + live OSS source)
  established the **current** APIs, correcting stale assumptions:
  - **GPU util** = IOKit `IOAccelerator` → `PerformanceStatistics["Device Utilization %"]`
    (same registry-walk flavor as `DiskSampler`). Low risk.
  - **Fans** = `AppleSMC` `FNum`/`F<i>Ac` keys via a small SMC reader. Lowest risk.
  - **Temps** = `IOHIDEventSystemClient` thermal sensors (per-SoC name churn). Highest
    risk → split to **D-018**.
  - **All permission-free** — no entitlement/root/sandbox-private. Cost is *stability*,
    never *permission*. (Confirms the existing D-014 MAS caveat; adds no new one.)
- Hardware confirmed: **M4 Pro (Mac16,8), arm64, has fans** → all three testable on
  this machine; no "can't verify on this hardware" gaps.

### Decisions (user-chosen)
- **Phased:** ship Fans+GPU first (D-017), Temps separately (D-018). Isolates the
  fragile IOHID path from the safe stats.
- **Temp tile (D-018) shows `ProcessInfo.thermalState`** (public, rock-stable) — the
  fragile per-sensor °C becomes best-effort *detail-card* content, not the headline.
  Turns the riskiest stat into one with a solid floor.

### Spec + plan
- `specs/gpu-fan-stats.md` — 8 ACs, traced wiring (`StatKind`→`StatDescriptor`→
  `visibleStats`), hide-when-absent mirroring Battery, free migration via `knownStats`.
- `IMPLEMENTATION_PLAN.md` — 4 waves. **Two parallel research agents fetched live
  `exelban/stats` source** (`SMC/smc.swift` + `Modules/GPU/reader.swift`) and the
  distilled, drop-in code is embedded in the plan so execution needs no re-research.

### Wave 1 executed (2 parallel `developer` agents, fresh context each)
- **`Sampling/SMC.swift`** — read-only `AppleSMC` reader. The load-bearing fact:
  `flt` decodes as **native little-endian** `Float`, integer types (`ui16`/`ui32`)
  are **big-endian** — older readers (SMCKit/osx-cpu-temp) only know `fpe2`/`sp78`
  and read garbage for the `flt` keys M-series uses. Field order matches the kernel
  ABI verbatim; constants 2/5/9; two-step `READ_KEYINFO`→`READ_BYTES`.
- **`Sampling/GPUSampler.swift`** (+ `GPUSample`) — `IOAccelerator` registry walk
  (`IOServiceMatching("IOAccelerator")`; `kIOAcceleratorClassName` isn't bridged to
  Swift → literal, documented in-file), `["PerformanceStatistics"]["Device Utilization %"]`
  ?? `"GPU Activity(%)"`, device name from `props["model"]`. Standard `DispatchSourceTimer`
  skeleton; not visibility-gated (cheap read).
- **Verification** — to avoid a parallel `xcodebuild`/`xcodegen` race on one working
  copy, each agent verified its file **standalone via `swiftc`** (both are pure
  Foundation+IOKit), then the orchestrator ran the single integrated build:
  - SMC: `FNum=2`, F0 range `2317–7826 rpm`, `F0Ac=0` (idle — Apple Silicon parks
    fans at 0 when cool; a real edge case the tile's `loadPercent` must handle). The
    sane rpm **proves the `flt` decode** (a big-endian misread prints ~6.4e9).
  - GPU: `isAvailable=true`, `15%`, `AGXAcceleratorG16X` (the M4 Pro GPU block) —
    confirms it read the right accelerator.
  - Integrated `xcodegen generate && xcodebuild` → `** BUILD SUCCEEDED **`, 0 warnings.

# Session 3 — 2026-06-15 (GPU + Fan stats: Waves 2–4 → D-017 SHIPPED)

**Focus:** Finish D-017 — `FanSampler` (Wave 2), wire both tiles into the strip
(Wave 3), and verify + migrate + document (Wave 4). Done inline (small, well-specced
waves; orchestrator already held the patterns) rather than via subagents.

## What happened

### Wave 2 — `Sampling/FanSampler.swift` + `FanSample`
- `FanSample{ hasFans, [Fan{current,min,max}] }`; `fastest` fan drives `headlineRPM`/
  `headlineFormatted`; `loadPercent` normalizes the fastest fan's current rpm in its
  own `[min,max]`, guarding `max>min` (unknown range ⇒ 0) and clamping 0–100 (so an
  idle fan reading below its rated min ⇒ 0, not negative).
- `FanSampler` mirrors the `GPUSampler` timer skeleton, holding **one** long-lived
  `SMC` connection, closed on `stop()`.
- **Course-correction:** first version confined the SMC to the queue via
  `queue.async { [weak self] … }` — that captured non-`Sendable` `self` in a
  `@Sendable` closure → 2 warnings (would fail AC-8). Root cause:
  `DispatchQueue.async` demands `@Sendable`, but `DispatchSourceTimer.setEventHandler`
  does **not** — so the existing samplers never hit this. Reverted to the idiomatic
  synchronous create/close; the cross-thread `smc` access is made safe by `SMC` itself
  (`value(forKey:)` guards `conn != 0`, `close()` zeroes it → a tick racing `stop()`
  just gets a nil and the final sample is discarded). Commit `1dc398a`.

### Wave 3 — wire `.gpu`/`.fan` into the strip (one compile unit)
- `StatKind` gained `.gpu`/`.fan` (after `.battery`) with `displayName` ("GPU"/"Fans")
  + `settingsSymbol` (`cpu.fill` ⚠ / `fanblades`). The exhaustive switches forced
  every display path to handle them — impossible to forget a name/symbol/tile.
- `StatsStore` publishes `gpu`/`fan` samples + owns `GPUSampler`/`FanSampler`, started
  **continuously** in `start()` (cheap reads, not visibility-gated), torn down in
  `stop()`; `restart()` cascades.
- `descriptor(for:)` renders both with Battery-style nil-gating: GPU hides on
  `!gpu.isAvailable`, Fan on `!fan.hasFans`. GPU detail = Utilization (+ Device when
  read); Fan detail = one row per fan, `"2100 rpm (1200–7800)"`. Commit `31bf97f`.

### Wave 4 — verify, migrate, document
- **Clean build** from scratch → `** BUILD SUCCEEDED **`, **0 Swift warnings** (AC-8).
- **On-screen (M4 Pro), user-confirmed:**
  - GPU tile live; detail card showed `Utilization 18% / Device AGXAcceleratorG16X`
    (the `IOClass` fallback — this Mac's accelerator exposes no `model` key). AC-1/AC-5 ✅
  - Fans read **0 rpm** cool-idle (genuine — `Fan 1/2: 0 rpm (2317–7826)`), then a
    12-core `yes` stress spun them to **2483 rpm**, in-range. A value *moving* 0→2483
    can only come from a correct live `flt` decode → **AC-3 + AC-6 ✅**.
  - **Migration (AC-7):** simulated an old user (`knownStats` without gpu/fan, Network
    deliberately off). Relaunch → `knownStats` rewritten to include gpu/fan (data
    layer); strip showed GPU+Fans ON appended **at the end**, Network **absent**
    (deliberately-off preserved). Restored real settings after. ✅
  - **Hide-paths (AC-2/AC-4):** verified by mechanism, **not** on real hardware — same
    `compactMap(descriptor(for:))` chokepoint was just watched dropping the Network
    tile cleanly (no gap/crash), and the `guard isAvailable/hasFans` + `.empty` flags

- **powermetrics dead-end:** tried `powermetrics --samplers smc` as a fan reference —

## D-019 — Power tile (watts) via IOReport "Energy Model" — SHIPPED

**Focus:** Build the user-requested Power tile from the ready `specs/power-stats.md`
+ `IMPLEMENTATION_PLAN.md` via wave-based `/execute`. Permission-free SoC watts from
Apple's private-but-un-entitled `IOReport` framework (the no-root path `macmon`/
`NeoAsitop` prove); `powermetrics` is out because it needs root (D-002/D-003).

### What happened — 4 waves, all on `main`, built 0 warnings, validated each wave

**Wave 1 — IOReport foundation (the whole risk, done in isolation first).** Commit
`5778f09`. Project's **first bridging header** (`QuickStatsPanel-Bridging-Header.h`)
with plain `extern` C decls for the un-headered IOReport symbols; linked via
`OTHER_LDFLAGS: -lIOReport` + `SWIFT_OBJC_BRIDGING_HEADER` in `project.yml` (resolves
in the dyld shared cache, no `dlopen`). New `Sampling/IOReport.swift` `IOReportPower`:
queue-confined "Energy Model" subscription, `read() -> (cpu,gpu,ane,dram)?` deltaing
cumulative energy counters per tick (ΔJoules÷Δseconds), routing channels by
prefix/suffix (multi-die safe), divisor from each channel's **runtime** unit label
(mJ/uJ/nJ — not hardcoded), full `Unmanaged`/CFRelease accounting, `isAvailable`
probed once at init. Caught + fixed a typedef tag/name collision (`struct
__IOReportSubscription*`). **Validated un-elevated (uid 501):** `isAvailable=true`,
idle ~0.5–1.2 W, **CPU rose to ~6 W under a 12-core `yes` load while GPU/ANE stayed
flat and DRAM ticked up** — correct routing + math (AC-1/AC-2/AC-8). De-risked exactly
like SMC.swift in D-017: prove the watts before building anything on top.

**Wave 2 — PowerSampler + PowerSample.** Commit `fa713ff`. `Sampling/PowerSampler.swift`
on the GPU/Fan `DispatchSourceTimer` skeleton, owning one `IOReportPower`. `PowerSample`
(Equatable/Sendable): CPU·GPU split `headlineFormatted` ("cpu·gpu W" integers), 1-decimal
detail formatters, computed `totalWatts` (CPU+GPU+ANE+DRAM), **stored** `loadPercent`.
Sample-building is a pure `makeSample(from:available:peak:)` shared by `tick()` and the
DEBUG dump. `peakTotal` ratchets up, resets in `start()`. Live dump: tick 0 = `"0·0 W"`
(AC-7 seed), headline `"6·0 W"` under load, **peak ratchets monotonically (6.55→7.18 W)
and loadPercent = total÷peak (saw 97% when total dipped below peak)** — AC-5.

**Wave 3 — wire into the strip (one compile unit).** Commit `0a520bd`. `.power` added to
`StatKind` (after `.fan`), `displayName "Power"`, `settingsSymbol "bolt.fill"`;
`descriptor(for: .power)` guards `power.isAvailable` (hide-gate), headline =
`headlineFormatted`, `widestValue "88·88 W"` (D-008 fixed slot), `loadPercent`, 5 detail
rows. `StatsStore` publishes `power` + owns `powerSampler`, started **un-gated** after
`fan`. The exhaustive `StatKind` switches forced full coverage. Clean from scratch, 0
warnings.

**Wave 4 — verify, migrate, document.** On screen (user, M4 Pro): ⚡ tile present in
position with the fixed-width slot (AC-3) and a 5-row detail card CPU/GPU/ANE/DRAM/Total
